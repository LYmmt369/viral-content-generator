# v4.1.0 验收范围

本版验收的是“材料成稿 → 一句话提出改法 → 精准应用 → 查看差异 → 准确撤回”的软件流程。

| 范围 | 验证方式 | 能证明什么 |
| --- | --- | --- |
| 编辑边界 | 单元测试及随机组合样例 | 只替换声明的原文片段，保留其他字符；可恢复原稿 UTF-8 字节 |
| 保护与版本 | 正反例 | 重复目标、重叠修改、缺失原句、保护冲突与过期版本被拒绝 |
| 自然语言入口 | 固定模型回复和 CLI 测试 | 一句话要求进入请求；模型无法取消保护或指定另一版原稿 |
| 成稿与落盘 | CLI 测试 | 材料和指令传递完整，来源版本被记录，已有文件不会被覆盖 |
| 失败处理 | 无效 JSON、重复字段、空回复、截断和源文件并发变化 | 不把错误回复或过期提议保存成新稿 |
| OpenAI / Claude | 真实 SDK 请求本地 HTTP 模拟服务 | 直接提示传递、请求参数、响应解析、失败不重试及截断拒绝 |
| Gemini | 已安装 SDK 方法签名及模拟返回 | 显式提示、输出预算、超时、关闭重试参数与适配方法一致 |
| 安装包 | Wheel 构建、安装后从源码目录外运行 | 模块和命令入口实际进入安装包 |
| 旧接口 | 回归测试 | 旧生成器调用可执行，主题参数一致，失败候选不会被保存 |

测试不调用付费模型。固定回复和本地模拟服务不证明真实模型的写作质量、改稿意图理解或事实正确性，也不证明发布效果。

模型接口部分使用 OpenAI Docs 核对当前的[重试与超时设置](https://developers.openai.com/api/reference/python)及[Chat Completions 参数](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)，再用实际 SDK 验证。没有增加自动 Skill 路由或主动询问流程。

## 可重复执行的检查

```bash
python -m pytest -q
python -S -m unittest discover -s tests -p test_revision.py -q
python -S examples/direct_drafting_demo.py --output output/direct-demo
python scripts/check_docs.py
python scripts/check_secrets.py
python scripts/validate_config.py data/accounts/default_account.yaml --kind account
python scripts/validate_config.py data/offers/default_offer.yaml --kind offer
python scripts/validate_config.py data/styles/global_creators.yaml --kind style
python scripts/list_styles.py
python -m build --wheel
pip-audit -r requirements.txt
```

CI 在 Python 3.10、3.11 和 3.12 上执行回归、离线演示、文档、配置、依赖审计和安装包检查。CI 结果以对应提交的 Actions 记录为准。

## 已知边界

- 模型给出替换范围，程序保证范围之外不变；是否选对范围要看 diff。
- 未明确保护的数字和事实仍可能被模型改写；程序不做自动事实核查。
- 来源指纹用于版本比对，不是作者身份或数字签名。
- 模型须由用户选择。OpenAI 适配要求支持 Chat Completions；Gemini 暂时保留原仓库的旧 SDK，未进行迁移。
- 旧的长度参考值仍只是启发式，不用于证明内容质量或传播表现。
