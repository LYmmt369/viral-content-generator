# v4.1 路线图

## 唯一优先方向

围绕一篇稿件，做好生成与精准修改。先验证“指定哪里改哪里、其他文字保持原样、重要原句可保护、改动可撤回”。

不扩展自动 Skill 路由、主动询问、通用商业诊断、知识库和多 Agent 中间层。不以 Skill 数量、风格卡数量或功能清单作为迭代目标。

## v4.1.0 已接通

已实现一个只使用 Python 标准库的[精准改稿内核](precise-revisions.md)：版本核验、原句定位、保护范围、整批校验、diff 和准确撤回。

write 从材料直接成稿，edit 把一句改法变为有限修改，revert 核验版本并准确撤回。模型接口复用现有适配器，每次工作流只生成一次，不加载旧 Skill。

## 验收与后续取舍

1. 作者用一句话说明修改要求；直接生成有限修改提议，不引入路由与访谈。
2. 提议通过内核检查后形成新稿；失败给出具体原因，不猜测位置或扩大改稿范围。
3. 当前已验证固定回复、真实 SDK 到本地模拟服务以及编辑边界；后续用真实改稿案例比较目标完成度、非目标内容保持和手工修复量，不提前宣称写作质量提升。

现有生成接口、平台输出和反馈计算中的基础问题，按实际接入需要修复。文档、打包、隐私与贡献入口作为维护工作继续保留。

## 4.1.5 基础修复

CLI 与 Python API 共用生成流程；多平台分别执行，全部通过再落盘。配置完整传递；反馈按作品、窗口和快照分开处理，缺分母为未知。当前 Skill 入口和安装包版本同步。真实云模型写作质量仍需实际稿件验收。
